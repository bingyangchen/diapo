# 講者模式的手動檢查

這份檔案列出 [presenter.md](../../docs/specs/presenter.md) 裡需要手動檢查的情境。改到和這些情境有關的程式碼時，照下面的步驟檢查，並把結果寫在 PR 的「手動檢查」。

下面的步驟都用測試用的簡報，因為這些簡報的頁面名稱和 spec 的情境相同：`annual-review`（標題是「年度回顧」）依序是 Intro、Agenda、Recap、Thanks 四頁，四頁都沒有頁內分步，Agenda、Recap、Thanks 都有比備註區長的備註。檢查之前先執行 `make build DECKS_DIR=tests/fixtures/decks`。步驟裡的「開啟簡報」指用瀏覽器開啟 `dist/annual-review/index.html`；要從網站開啟簡報時，再執行 `make serve`，步驟裡的 `<Local 網址>` 指這個指令在終端機印出的 Local 網址，通常是 `http://localhost:4173/`。

需要投影幕的步驟，用另一台螢幕代替投影幕，並在作業系統的顯示器設定裡設成延伸桌面；在 macOS 上，「系統設定」裡「桌面與 Dock」的「顯示器有不同的空間」要開著。

## PRES-R1.2 講者視窗已經開著

需要手動檢查的原因：Playwright 的每個視窗都在前景，所以 E2E test 只能確認播放器呼叫了講者視窗的 `focus()`，看不出講者視窗有沒有真的移到最前面。

1. 用 Chrome 開啟簡報。
2. 按 `S`。
3. 確認開啟了講者視窗。
4. 如果講者視窗比觀眾視窗大，把觀眾視窗拉大。
5. 點觀眾視窗，讓觀眾視窗蓋住講者視窗。
6. 按 `S`。
7. 在 Firefox 與 Safari 重複步驟 1 到 6。

預期：步驟 6 之後沒有開啟新的視窗，原本的講者視窗移到最前面。

## PRES-R1.5 在 Safari 開啟講者視窗

需要手動檢查的原因：Playwright 的 WebKit 不會擋下任何彈出視窗，所以 E2E test 看不出真正的 Safari 會不會擋下按 `S` 開出的視窗。

1. 確認 Safari 的「設定」裡「網站」的「彈出式視窗」使用預設值。
2. 用 Safari 開啟簡報。
3. 按 `S`。

預期：開啟講者視窗。

## PRES-R1.8 講者視窗開在獨立的視窗

需要手動檢查的原因：Playwright 把每個彈出視窗都當成一個 page，看不出瀏覽器把講者視窗開成獨立的視窗還是分頁。

1. 用 Chrome 開啟簡報。
2. 按 `S`。
3. 在 Firefox 與 Safari 重複步驟 1 到 2。

預期：講者視窗開在新的瀏覽器視窗，觀眾視窗所在的視窗沒有多出分頁。

## PRES-R1.10 瀏覽器視窗全螢幕時按 `S`

需要手動檢查的原因：E2E test 沒有投影幕，也做不出作業系統讓整個瀏覽器視窗全螢幕的狀態。

1. 在 macOS 上用 Chrome 開啟簡報。
2. 把觀眾視窗拖到投影幕上。
3. 點觀眾視窗左上角的綠色按鈕，讓觀眾視窗所在的瀏覽器視窗全螢幕。
4. 按 `S`。
5. 確認講者視窗出現在投影幕上、蓋在觀眾視窗上面，投影幕沒有切換到其他桌面空間。
6. 把講者視窗拖到筆電螢幕上。
7. 在 Firefox 與 Safari 重複步驟 1 到 6。

預期：步驟 5 的結果成立，而且在步驟 6 可以把講者視窗拖到筆電螢幕上。

## PRES-R1.15 觀眾視窗已經在投影幕上時開啟講者視窗

需要手動檢查的原因：E2E test 沒有投影幕，看不出瀏覽器把講者視窗開在哪個螢幕。

1. 用 Chrome 開啟簡報。
2. 把觀眾視窗拖到投影幕上，不要進入全螢幕。
3. 按 `S`。
4. 在 Firefox 與 Safari 重複步驟 1 到 3。

預期：講者視窗開在投影幕上。

## PRES-R1.16 瀏覽器封鎖彈出視窗時按 `S`

需要手動檢查的原因：E2E test 只能用瀏覽器預設的彈出視窗設定執行，沒辦法替一個網站封鎖彈出視窗。

1. 執行 `make serve`。
2. 在 Chrome 開啟 `chrome://settings/content/popups`。
3. 在「不得傳送彈出式視窗或使用重新導向」新增 `<Local 網址>`。
4. 開啟 `<Local 網址>annual-review/`。
5. 開啟 DevTools 的 Console。
6. 點簡報，讓焦點回到網頁。
7. 按 `S`。
8. 在 Safari 的「設定」裡「網站」的「彈出式視窗」，把 `localhost` 設成「阻擋」。
9. 用 Safari 重複步驟 4 到 7，Console 在「開發」選單的「顯示網頁檢閱器」裡。

預期：步驟 7 與步驟 9 之後，都沒有開啟講者視窗，畫面仍然顯示 Intro，Console 印出 `The browser blocked the presenter window` 開頭的警告。

## PRES-R1.17 瀏覽器封鎖彈出視窗時輸入頁碼途中按 `S`

需要手動檢查的原因：和 PRES-R1.16 相同，E2E test 沒辦法替一個網站封鎖彈出視窗。

1. 照 PRES-R1.16 的步驟 1 到 4 封鎖彈出視窗，並開啟簡報。
2. 在 3 秒內按 `3`、`S`、Enter。
3. 照 PRES-R1.16 的步驟 8 封鎖 Safari 的彈出視窗。
4. 用 Safari 開啟 `<Local 網址>annual-review/`。
5. 在 3 秒內按 `3`、`S`、Enter。

預期：步驟 2 與步驟 5 按 `S` 之後，右下角的頁碼消失，按 Enter 之後，畫面顯示 Agenda。

## PRES-R1.18 在 Windows 按 F11 讓瀏覽器視窗全螢幕時按 `S`

需要手動檢查的原因：E2E test 沒有投影幕，也做不出作業系統讓整個瀏覽器視窗全螢幕的狀態。

預期：步驟 5 的結果成立，而且在步驟 6 可以把講者視窗拖到筆電螢幕上。

## PRES-R1.19 講者視窗縮到最小時按 `S`

需要手動檢查的原因：Playwright 沒辦法把視窗縮到最小，也看不出網頁呼叫 `focus()` 之後，瀏覽器有沒有還原縮到最小的視窗。

1. 用 Chrome 開啟簡報。
2. 按 `S`。
3. 把講者視窗縮到最小。
4. 點觀眾視窗。
5. 按 `S`。
6. 在 Firefox 與 Safari 重複步驟 1 到 5。

預期：步驟 5 之後，講者視窗還原，並移到最前面。

## PRES-R3.2 在講者視窗跳頁後回到原來的頁面

需要手動檢查的原因：網頁沒有收到使用者的操作就新增瀏覽紀錄時，Chrome 的上一頁按鈕可能跳過這筆紀錄，而 Playwright 的 `goBack()` 不經過上一頁按鈕。

1. 用 Chrome 開啟簡報。
2. 按 →。
3. 確認畫面顯示 Agenda。
4. 按 `S`。
5. 點講者視窗。
6. 按 End。
7. 確認觀眾視窗顯示 Thanks。
8. 點觀眾視窗工具列上的上一頁按鈕。
9. 確認觀眾視窗與講者視窗的目前頁都顯示 Agenda。
10. 重新整理觀眾視窗。
11. 等講者視窗的「連線中斷」消失。
12. 點講者視窗。
13. 按 End。
14. 點觀眾視窗工具列上的上一頁按鈕。

預期：步驟 9 的結果成立；步驟 14 之後，觀眾視窗與講者視窗的目前頁都顯示 Agenda。

## PRES-R3.6 焦點在講者視窗時用翻頁器換頁

需要手動檢查的原因：E2E test 只能送出模擬的 keydown 事件，所以要用真正的翻頁器確認翻頁器送出的 keydown 事件會送到講者視窗。

1. 把翻頁器接上電腦。
2. 用 Chrome 開啟簡報。
3. 按 `S`。
4. 點講者視窗。
5. 按翻頁器的下一頁鍵。

預期：觀眾視窗顯示 Agenda。

## PRES-R3.23 在講者視窗連續跳頁兩次之後回到上一頁

需要手動檢查的原因：和 PRES-R3.2 相同，Chrome 的上一頁按鈕可能跳過網頁沒有收到使用者操作就新增的瀏覽紀錄。

1. 用 Chrome 開啟簡報。
2. 按 →。
3. 按 `S`。
4. 點講者視窗。
5. 按 End。
6. 按 Home。
7. 確認觀眾視窗顯示 Intro。
8. 點觀眾視窗工具列上的上一頁按鈕。

預期：觀眾視窗與講者視窗的目前頁都顯示 Thanks。

## PRES-R4.2 兩個螢幕各自全螢幕

需要手動檢查的原因：E2E test 沒有投影幕，headless 的瀏覽器也沒有作業系統的桌面空間。

1. 用 Chrome 開啟簡報。
2. 按 `S`。
3. 把觀眾視窗拖到投影幕上，講者視窗留在筆電螢幕上。
4. 點觀眾視窗。
5. 按 `F`。
6. 點講者視窗。
7. 按 `F`。
8. 在 Firefox 與 Safari 重複步驟 1 到 7。

預期：觀眾視窗在投影幕上全螢幕，講者視窗在筆電螢幕上全螢幕，兩個視窗同時維持全螢幕。

## PRES-R4.3 焦點在講者視窗時按翻頁器的播放鍵

需要手動檢查的原因：翻頁器的播放鍵送出的是 F5 或 Shift+F5，而在 Playwright 裡按 F5 時，就算播放器沒有擋下，網頁也不會重新載入，所以 E2E test 看不出播放器有沒有擋下播放鍵造成的重新整理。

1. 把翻頁器接上電腦。
2. 用 Chrome 開啟簡報。
3. 按 →。
4. 按 `S`。
5. 用觸控板把講者視窗的備註區捲到最下方。
6. 點講者視窗的標題列。
7. 按翻頁器的播放鍵。

預期：講者視窗進入全螢幕，備註區仍然捲在最下方，觀眾視窗仍然不在全螢幕。

## PRES-R6.9 觀眾視窗的分頁不在前景

需要手動檢查的原因：Playwright 的分頁一律在前景，E2E test 只能模擬分頁不在前景的狀態，所以要用真正的瀏覽器確認播放器收得到這個狀態。

1. 用 Chrome 開啟簡報。
2. 按 `S`。
3. 點觀眾視窗。
4. 按 Cmd+T（Windows 按 Ctrl+T）開一個新的分頁。
5. 確認講者視窗的目前頁仍然顯示 Intro，上面疊著「觀眾看不到簡報」。
6. 切回觀眾視窗的分頁。
7. 在 Firefox 與 Safari 重複步驟 1 到 6。

預期：步驟 5 的結果成立；步驟 6 之後，「觀眾看不到簡報」消失。

## PRES-R6.10 觀眾視窗縮到最小

4. 確認講者視窗的目前頁上面疊著「觀眾看不到簡報」。
5. 把觀眾視窗還原。
6. 在 Firefox 與 Safari 重複步驟 1 到 5。

預期：步驟 4 的結果成立；步驟 5 之後，「觀眾看不到簡報」消失。

## PRES-R9.14 複製觀眾視窗的分頁

需要手動檢查的原因：Playwright 沒辦法複製分頁。

1. 用 Chrome 開啟簡報。
2. 按 `S`。
3. 點講者視窗的經過時間。
4. 等經過時間超過 `00:10`。
5. 在觀眾視窗的分頁上按右鍵，選「複製」。
6. 在複製出來的分頁按 `S`。
7. 確認開啟了新的講者視窗。
8. 等 3 秒，比對兩個講者視窗的經過時間。
9. 在複製出來的分頁按 →。
10. 在 Firefox 與 Safari 重複步驟 1 到 9，步驟 5 改選分頁右鍵選單裡的「複製分頁」。

預期：步驟 8 時，新的講者視窗的經過時間和原本的講者視窗相同，相差不到 1 秒；步驟 9 之後，原本的講者視窗的目前頁仍然顯示 Intro。

## PRES-R9.15 還原誤關的觀眾視窗

需要手動檢查的原因：Playwright 沒辦法用 Cmd+Shift+T 還原關掉的分頁，所以 E2E test 驗證不了各瀏覽器還原分頁時會不會帶回 `sessionStorage`。

1. 用 Chrome 開啟簡報。
2. 按 `S`。
3. 點講者視窗的經過時間。
4. 記下開始計時的時刻。
5. 關掉觀眾視窗。
6. 確認講者視窗跟著關閉。
7. 按 Cmd+Shift+T（Windows 按 Ctrl+Shift+T）。
8. 記下 Cmd+Shift+T 還原的是觀眾視窗，還是只顯示「請在簡報裡按 S 開啟講者視窗」的視窗。
9. 如果還原的是只顯示「請在簡報裡按 S 開啟講者視窗」的視窗，再按一次 Cmd+Shift+T。
10. 確認還原出觀眾視窗。
11. 在觀眾視窗按 `S`。
12. 等 3 秒，比對新開啟的講者視窗顯示的經過時間，和從步驟 4 記下的時刻到現在過了多久。
13. 在 Firefox 與 Safari 重複步驟 1 到 12。

預期：步驟 12 時，經過時間等於從步驟 4 記下的時刻到現在過了多久，包含觀眾視窗關著的那段時間。把每個瀏覽器在步驟 8 記下的結果寫在 PR 的「手動檢查」裡。

## PRES-R11.3 按 Tab 之後按 Space

需要手動檢查的原因：Playwright 送出的 keydown 事件直接進到網頁，所以 E2E test 看不出網頁擋下 Tab 之後，瀏覽器會不會仍然把焦點移到網址列。

1. 用 Chrome 開啟簡報。
2. 按 `S`。
3. 點講者視窗的經過時間。
4. 點講者視窗的備註區。
5. 按五次 Tab。
6. 按 Space。
7. 在 Firefox 重複步驟 1 到 6。
8. 在 Safari 重複步驟 1 到 6，步驟 5 改按五次 Option+Tab。
9. 在 Safari 重複步驟 1 到 6，步驟 5 照原本的寫法按五次 Tab。

預期：每次按 Space 之後，觀眾視窗都顯示 Agenda，講者視窗的經過時間沒有變成「未開始」。

## PRES-R11.4 按 Shift+Tab 之後按 Space

## PRES-R13.5 用瀏覽器的上一頁回到回應 COOP 的網頁

需要手動檢查的原因：和 PRES-R13.4 相同，E2E test 驗證不了瀏覽器會不會因為 `Cross-Origin-Opener-Policy` 切斷兩個視窗之間的關係。

1. 執行 `make serve`。
2. 如果 `<Local 網址>` 不是 `http://localhost:4173/`，把下一步指令裡的 `http://localhost:4173/` 改成 `<Local 網址>`。
3. 在另一個終端機執行下面的指令，啟動一個在 `http://localhost:8000/` 回應 `Cross-Origin-Opener-Policy: same-origin` 的 server，這個 server 回應的網頁上只有一個連到簡報的「年度回顧」連結。

   ```sh
   node -e 'require("node:http").createServer((request, response) => { response.setHeader("Cross-Origin-Opener-Policy", "same-origin"); response.setHeader("Content-Type", "text/html; charset=utf-8"); response.end("<a href=\"http://localhost:4173/annual-review/\">年度回顧</a>"); }).listen(8000)'
   ```

4. 用 Chrome 開啟 `http://localhost:8000/`。
5. 點「年度回顧」。
6. 按 `S`。
7. 點觀眾視窗工具列上的上一頁按鈕。
8. 在 Firefox 與 Safari 重複步驟 4 到 7。

預期：步驟 7 之後，講者視窗跟著關閉。
