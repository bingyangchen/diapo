# 講者模式

講者模式是講者把電腦接上投影幕播放簡報時，在自己的螢幕上看著目前頁、下一步、下一頁、講者備註與時間的能力。講者在播放簡報的視窗按 `S`，播放器另外開一個講者視窗；原本播放簡報的視窗叫做觀眾視窗，投影幕上顯示的就是觀眾視窗。講者視窗顯示觀眾視窗目前的頁面與步驟；講者在講者視窗也能用快捷鍵操作簡報，規則寫在 PRES-R3。

講者視窗載入同一份 slidetray，由同一個播放器 render，不過其他 spec 的需求只有一部分適用於講者視窗：

- [playback.md](playback.md) 與 [navigation.md](navigation.md) 的需求只描述觀眾視窗。
- [steps.md](steps.md) 裡，`<Step>` 與 `useStep` 決定畫面的規則（STEP-R1 到 STEP-R8）也適用於講者視窗的目前頁、下一步與下一頁，換頁與網址 hash 的規則（STEP-R9 到 STEP-R14）只描述觀眾視窗。
- [overview.md](overview.md) 同時描述兩個視窗的總覽，講者視窗連上時（定義寫在 OVW-R26），兩個視窗共用同一個總覽（OVW-R17），總覽只顯示在講者視窗。講者視窗開著總覽時，按鍵的作用照 overview.md 的 OVW-R12，所以 PRES-R10 與 PRES-R11 寫的 Space、Enter、PageDown 與 ↓ 的作用，只描述總覽沒有開著的時候。
- 除了 overview.md，講者視窗只套用本 spec 明確引用的需求，例如 PRES-R3 引用的快捷鍵規則，以及 PRES-R4 引用的 NAV-R10。

講者模式只支援電腦上的瀏覽器，平板與手機不支援。講者開啟講者視窗之後，自己把觀眾視窗拖到投影幕上，在觀眾視窗按 `F` 進入全螢幕，講者視窗留在自己的螢幕上。在 macOS 上，「系統設定」裡「桌面與 Dock」的「顯示器有不同的空間」要開著，這也是 macOS 的預設值，否則一個螢幕上的視窗進入全螢幕時，另一個螢幕會變黑；播放器偵測不到這項設定。

> 設計理由：講者手動把觀眾視窗拖到投影幕。曾考慮在講者按 `S` 時，用 Window Management API 讓觀眾視窗在外接螢幕上全螢幕、講者視窗開在筆電螢幕上，但從 `file://` 開啟時只有 Chromium 支援這個 API，第一次使用時還要講者授權，所以講者換到 Firefox、Safari 或現場的電腦時，開講前的操作就不一樣；接了兩個以上的外接螢幕時，也要另訂規則決定把觀眾視窗放在哪一個外接螢幕。完整討論見 [0004](../plans/archive/0004-presenter-mode.md)。

## 需求

### PRES-R1 用 `S` 開啟講者視窗

在觀眾視窗按 `S` 時，播放器開啟講者視窗。講者視窗是獨立的瀏覽器視窗，不是分頁，所以可以單獨拖到另一個螢幕。

- 瀏覽器通常把講者視窗開在觀眾視窗所在的螢幕，所以觀眾視窗已經在投影幕上時再按 `S`，例如講者誤關講者視窗之後，講者視窗會先出現在投影幕上，講者要把它拖回自己的螢幕。
- 瀏覽器擋下講者視窗時，例如講者在瀏覽器的設定裡封鎖了這份簡報的彈出視窗，按 `S` 只會照 NAV-R5 取消輸入中的頁碼，播放器另外在瀏覽器的 console 印出警告。
- 這個觀眾視窗開啟的講者視窗已經開著時，按 `S` 會把既有的講者視窗移到最前面，不會再開一個。
- 觀眾視窗在全螢幕時，按 `S` 只會照 NAV-R5 取消輸入中的頁碼。這裡的全螢幕指 NAV-R10 的全螢幕；講者用瀏覽器或作業系統讓整個瀏覽器視窗全螢幕時，例如按 macOS 視窗的綠色按鈕，按 `S` 照常開啟講者視窗。
- 講者在講者視窗按 `S` 的規則寫在 PRES-R3。
- `S` 和其他快捷鍵一樣適用 [navigation.md](navigation.md) 的 NAV-R7，黑畫面時的行為寫在 NAV-R9；按住 `S` 不放時，`S` 和其他快捷鍵一樣照常連續觸發（NAV-R14），但講者視窗開啟之後就不會再開一個。

> 設計理由：觀眾視窗在全螢幕時按 `S` 沒有作用，因為網頁開啟新視窗，或把其他視窗移到最前面時，瀏覽器會讓全螢幕的網頁離開全螢幕，投影幕上的觀眾就會看到瀏覽器的工具列或桌面。講者照開頭的說明，先按 `S` 開啟講者視窗、再在觀眾視窗按 `F` 時，不受這條規則影響。
>
> 曾考慮照常開啟講者視窗或移到最前面，並在 spec 寫明觀眾視窗會離開全螢幕，但演講途中講者按 `S`，多半是要找回被其他視窗蓋住的講者視窗，這時觀眾視窗離開全螢幕會打斷演講，而講者可以從 Dock 或工作列找回講者視窗；而且各瀏覽器在移到最前面時的結果不一樣。
>
> 講者用瀏覽器或作業系統讓整個瀏覽器視窗全螢幕時，按 `S` 照常開啟講者視窗，因為網頁沒有可靠的方式偵測這種全螢幕。完整討論見 [0004](../plans/archive/0004-presenter-mode.md)。

情境：

- PRES-R1.1 開啟講者視窗
  - 前提：講者視窗沒有開啟，畫面顯示 `agenda`
  - 動作：按 `S`
  - 結果：開啟講者視窗，講者視窗的目前頁顯示 `agenda`
- PRES-R1.2 講者視窗已經開著
  - 前提：觀眾視窗已經開啟講者視窗，講者視窗在觀眾視窗後面
  - 動作：在觀眾視窗按 `S`
  - 結果：沒有開啟新的視窗，既有的講者視窗移到最前面
- PRES-R1.3 觀眾視窗重新整理後再按 `S`
  - 前提：觀眾視窗已經開啟講者視窗
  - 動作：重新整理觀眾視窗，再在觀眾視窗按 `S`
  - 結果：沒有開啟新的視窗
- PRES-R1.4 在講者視窗按 `S`
  - 前提：講者視窗已經開著，焦點在講者視窗
  - 動作：按 `S`
  - 結果：沒有開啟新的視窗
- PRES-R1.5 在 Safari 開啟講者視窗
  - 前提：在 macOS 的 Safari 用 `file://` 開啟簡報，Safari 使用預設的彈出視窗設定
  - 動作：按 `S`
  - 結果：開啟講者視窗
- PRES-R1.6 觀眾視窗在全螢幕時按 `S`
  - 前提：講者視窗沒有開啟，觀眾視窗在全螢幕
  - 動作：按 `S`
  - 結果：沒有開啟講者視窗，觀眾視窗仍然在全螢幕
- PRES-R1.7 講者視窗已經開著時在全螢幕的觀眾視窗按 `S`
  - 前提：觀眾視窗已經開啟講者視窗，講者視窗在觀眾視窗後面，接著觀眾視窗進入全螢幕
  - 動作：在觀眾視窗按 `S`
  - 結果：講者視窗沒有移到最前面，觀眾視窗仍然在全螢幕
- PRES-R1.8 講者視窗開在獨立的視窗
  - 前提：瀏覽器使用預設的設定，講者視窗沒有開啟
  - 動作：按 `S`
  - 結果：講者視窗開在新的瀏覽器視窗，觀眾視窗所在的視窗沒有多出分頁
- PRES-R1.9 按住 `S` 不放
  - 前提：講者視窗沒有開啟
  - 動作：按住 `S`，直到作業系統自動送出好幾次 `S`
  - 結果：只開啟一個講者視窗
- PRES-R1.10 瀏覽器視窗全螢幕時按 `S`
  - 前提：筆電用延伸桌面接上投影幕，macOS 開著「顯示器有不同的空間」，觀眾視窗在投影幕上，講者按 macOS 視窗的綠色按鈕，讓觀眾視窗所在的瀏覽器視窗全螢幕，講者視窗沒有開啟
  - 動作：在觀眾視窗按 `S`
  - 結果：開啟講者視窗，講者視窗出現在投影幕上、蓋在觀眾視窗上面，投影幕沒有切換到其他桌面空間；講者能把講者視窗拖到筆電螢幕上
- PRES-R1.11 輸入頁碼途中按 `S`
  - 前提：講者視窗沒有開啟，觀眾視窗不在全螢幕，簡報依序是 `intro`、`agenda`、`recap` 三頁，觀眾視窗顯示 `intro`
  - 動作：在 3 秒內完成以下動作：在觀眾視窗輸入 3，按 `S`，點觀眾視窗，再按 Enter
  - 結果：按 `S` 之後，開啟講者視窗，觀眾視窗不再顯示頁碼；按 Enter 之後，觀眾視窗顯示 `agenda`
- PRES-R1.12 觀眾視窗在全螢幕時輸入頁碼途中按 `S`
  - 前提：講者視窗沒有開啟，觀眾視窗在全螢幕，簡報依序是 `intro`、`agenda`、`recap` 三頁，觀眾視窗顯示 `intro`
  - 動作：在 3 秒內完成以下動作：輸入 3，按 `S`，再按 Enter
  - 結果：按 `S` 之後，沒有開啟講者視窗，觀眾視窗不再顯示頁碼；按 Enter 之後，觀眾視窗顯示 `agenda`
- PRES-R1.13 觀眾視窗在全螢幕而且是黑畫面時按 `S`
  - 前提：觀眾視窗已經開啟講者視窗，講者視窗在觀眾視窗後面，觀眾視窗在全螢幕，接著切換成黑畫面
  - 動作：在觀眾視窗按 `S`
  - 結果：講者視窗沒有移到最前面，觀眾視窗仍然在全螢幕，仍然是黑畫面
- PRES-R1.14 黑畫面時把既有的講者視窗移到最前面
  - 前提：觀眾視窗已經開啟講者視窗，講者視窗在觀眾視窗後面，觀眾視窗不在全螢幕，接著切換成黑畫面
  - 動作：在觀眾視窗按 `S`
  - 結果：講者視窗移到最前面，觀眾視窗仍然是黑畫面
- PRES-R1.15 觀眾視窗已經在投影幕上時開啟講者視窗
  - 前提：筆電用延伸桌面接上投影幕，觀眾視窗在投影幕上，不在全螢幕，講者視窗沒有開啟
  - 動作：在觀眾視窗按 `S`
  - 結果：講者視窗開在投影幕上
- PRES-R1.16 瀏覽器封鎖彈出視窗時按 `S`
  - 前提：講者在瀏覽器的設定裡封鎖了這份簡報的彈出視窗，觀眾視窗顯示 `intro`
  - 動作：按 `S`
  - 結果：沒有開啟講者視窗，觀眾視窗仍然顯示 `intro`，瀏覽器的 console 印出警告
- PRES-R1.17 瀏覽器封鎖彈出視窗時輸入頁碼途中按 `S`
  - 前提：講者在瀏覽器的設定裡封鎖了這份簡報的彈出視窗，簡報依序是 `intro`、`agenda`、`recap` 三頁，觀眾視窗顯示 `intro`
  - 動作：在 3 秒內完成以下動作：輸入 3，按 `S`，再按 Enter
  - 結果：按 `S` 之後，觀眾視窗不再顯示頁碼；按 Enter 之後，觀眾視窗顯示 `agenda`
- PRES-R1.18 在 Windows 按 F11 讓瀏覽器視窗全螢幕時按 `S`
  - 前提：在 Windows 用延伸桌面接上投影幕，觀眾視窗在投影幕上，講者按 F11 讓觀眾視窗所在的瀏覽器視窗全螢幕，講者視窗沒有開啟
  - 動作：在觀眾視窗按 `S`
  - 結果：開啟講者視窗，講者視窗出現在投影幕上；講者能把講者視窗拖到筆電螢幕上
- PRES-R1.19 講者視窗縮到最小時按 `S`
  - 前提：觀眾視窗已經開啟講者視窗，觀眾視窗不在全螢幕，講者把講者視窗縮到最小
  - 動作：在觀眾視窗按 `S`
  - 結果：講者視窗還原，並移到最前面

> 設計理由：講者只能用 `S` 開啟講者視窗，因為講者模式只在接著投影幕的電腦上使用，講者一定有鍵盤。
>
> 曾考慮在全螢幕按鈕旁邊另外放一顆開啟講者視窗的按鈕，但平板與手機不支援講者模式，所以播放器得先判斷裝置能不能開獨立視窗，才能決定要不要顯示這顆按鈕。完整討論見 [0004](../plans/archive/0004-presenter-mode.md)。

### PRES-R2 講者視窗顯示觀眾視窗目前的位置

觀眾視窗的頁面、步驟或黑畫面改變時，講者視窗跟著更新。不論改變是講者在哪個視窗按下快捷鍵造成的，還是觀眾視窗的網址 hash 改變造成的，例如講者在觀眾視窗按了瀏覽器的上一頁，講者視窗都會更新。

情境：

- PRES-R2.1 在觀眾視窗換頁
  - 前提：講者視窗已經開著，觀眾視窗顯示 `intro`，下一頁是 `agenda`
  - 動作：在觀眾視窗按 →
  - 結果：講者視窗的目前頁顯示 `agenda`
- PRES-R2.2 在觀眾視窗按瀏覽器的上一頁
  - 前提：講者視窗已經開著，觀眾視窗顯示 `agenda`，講者在觀眾視窗按 End 跳到 `recap`
  - 動作：在觀眾視窗按瀏覽器的上一頁
  - 結果：講者視窗的目前頁顯示 `agenda`

### PRES-R3 在講者視窗操作簡報

講者在講者視窗按下按鍵時，播放器依 [navigation.md](navigation.md) 開頭的流程圖決定要做什麼，再照 navigation.md、[steps.md](steps.md) 與 [overview.md](overview.md) 的規則操作觀眾視窗。這張流程圖的判斷裡，是不是黑畫面、總覽有沒有開著看觀眾視窗，連線中斷或兩個視窗的版本不同時，看講者視窗最後一次正常連線時收到的狀態；其他判斷都看講者視窗，例如講者有沒有同時按著 Ctrl、Cmd 或 Alt、焦點在哪裡、是不是正在輸入頁碼。講者在講者視窗操作簡報時，和在觀眾視窗操作有以下差別：

1. 全螢幕的快捷鍵只作用在講者視窗（PRES-R4）。
2. 兩個視窗各自有一份輸入中的頁碼。講者在講者視窗輸入的頁碼只顯示在講者視窗，位置照 PRES-R8 與 OVW-R19；講者在講者視窗按 Enter 時，觀眾視窗跳到這一頁。一個視窗的快捷鍵不會取消另一個視窗的輸入，但觀眾視窗的頁面或步驟改變、切換黑畫面，或開啟、關閉總覽時，兩個視窗的輸入都會取消。
3. 跳頁新增的瀏覽紀錄在觀眾視窗，要回到跳頁之前的頁面時，講者要在觀眾視窗按瀏覽器的上一頁（NAV-R6）。講者視窗不讀取也不改寫網址的 hash，所以講者在講者視窗按瀏覽器的上一頁或下一頁，或改了講者視窗網址的 hash 時，兩個視窗都不會換頁。

   不過在 Chrome 這類以 Chromium 為基礎的瀏覽器上，從觀眾視窗重新載入簡報開始，到觀眾視窗收到講者的使用者操作為止，這段期間講者在講者視窗跳頁的話，點觀眾視窗工具列上的上一頁按鈕會略過這份簡報的所有頁面，回到開啟簡報之前的網頁；開啟簡報之前沒有其他網頁時，上一頁按鈕不能按。這時講者先點一下觀眾視窗畫面上沒有按鈕或連結的地方，再點上一頁按鈕，觀眾視窗就會回到跳頁之前的頁面。

   重新載入簡報指講者重新整理觀眾視窗，或在觀眾視窗離開簡報之後再回到簡報。使用者操作指講者點觀眾視窗的畫面，或在觀眾視窗按下會送到網頁的按鍵，例如 →，但 Esc 與只按 Ctrl、Cmd、Alt 或 Shift 不算，詳細的規則寫在 [architecture.md](architecture.md) 的「講者視窗」一節。本 spec 其他在觀眾視窗按瀏覽器的上一頁的情境，觀眾視窗在講者按 `S` 之後都沒有重新載入簡報。
4. `S` 在講者視窗不是播放器的快捷鍵，所以講者在講者視窗按 `S` 時，不會取消頁碼的輸入，也不會結束黑畫面。
5. 講者在講者視窗觸控滑動時，播放器不換頁、不結束黑畫面，也不取消頁碼的輸入（NAV-R5、NAV-R8、NAV-R9），因為講者在觸控螢幕上用手指左右捲動備註裡比較寬的程式碼區塊時，這個動作會被當成滑動。
6. Tab 這類移動焦點的鍵照 PRES-R11 由講者視窗擋下。

> 設計理由：講者在講者視窗按下按鍵時，除了是不是黑畫面與總覽有沒有開著，播放器都看講者視窗的狀態決定要做什麼，因為講者是對著講者視窗按下按鍵的；黑畫面與總覽則看觀眾視窗，因為這兩個狀態是兩個視窗共用的，以觀眾視窗為準。
>
> 曾考慮全部看觀眾視窗，但講者有沒有同時按著 Ctrl、Cmd 或 Alt，只有講者視窗收到的 keydown 事件看得出來；而且講者在投影幕上點過頁面的按鈕之後，焦點會留在觀眾視窗的按鈕上，講者在講者視窗按 Space 時快捷鍵不觸發（NAV-R7），畫面沒有任何反應，講者又看不到投影幕上的游標，不知道原因。
>
> 兩個視窗各自有一份輸入中的頁碼，因為輸入中的頁碼如果只有觀眾視窗那一份，講者在講者視窗輸入的頁碼就會顯示在投影幕上。完整討論見 [0004](../plans/archive/0004-presenter-mode.md) 與 [0005](../plans/archive/0005-overview.md)。

> 也考慮過只讓講者視窗接受快捷鍵，但沒開講者視窗時觀眾視窗仍然要接受快捷鍵，關掉講者視窗時又要恢復，規則反而變多。完整討論見 [0004](../plans/archive/0004-presenter-mode.md)。

### PRES-R4 全螢幕只作用在講者按下快捷鍵的視窗

講者在講者視窗按全螢幕的快捷鍵時，講者視窗照 NAV-R10 的規則切換全螢幕，觀眾視窗不受影響。瀏覽器只在一個視窗收到講者的操作時，才允許這個視窗進入全螢幕，所以講者在講者視窗沒辦法讓觀眾視窗進入全螢幕；講者要讓觀眾視窗在投影幕上全螢幕時，要在觀眾視窗按 `F`。

情境：

- PRES-R4.1 在講者視窗按 `F`
  - 前提：講者視窗與觀眾視窗都不在全螢幕，焦點在講者視窗
  - 動作：按 `F`
  - 結果：講者視窗進入全螢幕，觀眾視窗仍然不在全螢幕
- PRES-R4.2 兩個螢幕各自全螢幕
  - 前提：筆電用延伸桌面接上投影幕，在 macOS 上開著「顯示器有不同的空間」，觀眾視窗在投影幕上，講者視窗在筆電螢幕上，兩個視窗都不在全螢幕
  - 動作：在觀眾視窗按 `F`，再點講者視窗，按 `F`
  - 結果：觀眾視窗在投影幕上全螢幕，講者視窗在筆電螢幕上全螢幕，兩個視窗同時維持全螢幕
- PRES-R4.3 焦點在講者視窗時按翻頁器的播放鍵
  - 前提：筆電接上翻頁器，焦點在講者視窗，講者把講者視窗的備註區捲到最下方，兩個視窗都不在全螢幕
  - 動作：按翻頁器的播放鍵
  - 結果：講者視窗進入全螢幕，備註區仍然捲在最下方，觀眾視窗仍然不在全螢幕

### PRES-R5 講者視窗的版面

講者視窗照下圖排版，用深色背景與淺色文字，不受簡報配色的影響。目前頁、下一步與下一頁都把 1920×1080 的畫布等比縮放到各自的格子裡，下一步與下一頁的格子分別標上「下一步」與「下一頁」。

```text
┌───────────────────────────────────────────────────────────────┐
│ 經過時間 [歸零]  目前時刻  第 4 / 12 頁  第 1 / 3 步  輸入中的頁碼  │
├──────────────────────────────────────┬────────────────────────┤
│                                      │ 下一步                  │
│                                      │                        │
│ 目前頁                                ├────────────────────────┤
│                                      │ 下一頁                  │
│                                      │                        │
├──────────────────────────────────────┴────────────────────────┤
│ 講者備註                                                       │
│                                                               │
└───────────────────────────────────────────────────────────────┘
```

講者視窗的標題是 `deck.json` 的 `title` 加上「（講者視窗）」。講者視窗不隱藏游標（NAV-R12），也不顯示全螢幕按鈕（NAV-R11）。

情境：

- PRES-R5.1 視窗標題
  - 前提：`deck.json` 的 `title` 是 `年度回顧`
  - 動作：開啟講者視窗
  - 結果：講者視窗的標題是 `年度回顧（講者視窗）`
- PRES-R5.2 滑鼠停止移動 2 秒
  - 前提：游標在講者視窗上
  - 動作：2 秒內不移動滑鼠
  - 結果：游標仍然顯示
- PRES-R5.3 講者視窗沒有全螢幕按鈕
  - 前提：講者視窗已經開著，瀏覽器支援讓網頁元素進入全螢幕
  - 動作：在講者視窗移動滑鼠
  - 結果：講者視窗的右下角沒有出現全螢幕按鈕

> 設計理由：講者視窗不顯示上一頁。曾考慮在目前頁的左邊多放一格上一頁，但講者很少需要回頭看上一頁，多一格就會壓縮備註的空間，而備註是講者視窗裡最需要大字的部分。完整討論見 [0004](../plans/archive/0004-presenter-mode.md)。

### PRES-R6 目前頁

目前頁顯示觀眾視窗目前的頁面與步驟。

- 講者視窗 render 自己的一份頁面，所以講者在觀眾視窗操作互動元件之後，講者視窗的目前頁仍然顯示這一頁在目前步驟、沒有操作過互動元件的畫面。
- 目前頁、下一步與下一頁都不能操作：講者點不到裡面的元素，不能用 Tab 把焦點移進去，裡面的元素也不會取得焦點，包括寫了 `autoFocus` 或元件自己呼叫 `focus()` 的元素；裡面的元件也收不到鍵盤事件，所以不會攔下講者在講者視窗按的快捷鍵（NAV-R7）。
- 觀眾視窗是黑畫面時，目前頁照常顯示頁面，上面疊一層半透明的黑色遮罩，寫著「觀眾看到黑畫面」。
- 觀眾視窗的分頁不在前景時，例如講者在同一個瀏覽器視窗切到其他分頁，或把觀眾視窗縮到最小，目前頁上面改疊一層半透明的遮罩，寫著「觀眾看不到簡報」，觀眾視窗同時是黑畫面時也一樣；觀眾視窗的分頁回到前景之後，「觀眾看不到簡報」的遮罩消失。觀眾視窗的分頁不在前景的期間，講者的快捷鍵照常作用，所以講者在觀眾看其他分頁時，可以先換到之後要講的那一頁。
- 播放器偵測得到的只有分頁不在前景與視窗縮到最小，所以觀眾視窗被其他應用程式的視窗蓋住，或投影幕沒有顯示筆電的畫面時，講者視窗不一定會疊上「觀眾看不到簡報」的遮罩。

情境：

- PRES-R6.1 顯示目前的步驟
  - 前提：`list` 這一頁有 3 步，觀眾視窗顯示 `list` 的第 2 步
  - 動作：按 `S`
  - 結果：講者視窗的目前頁顯示 `list` 的第 2 步
- PRES-R6.2 點不到目前頁上的按鈕
  - 前提：觀眾視窗顯示 `counter`，這一頁有一個計數器，初始值是 0
  - 動作：在講者視窗點目前頁上的計數器
  - 結果：講者視窗與觀眾視窗的計數器都顯示 0
- PRES-R6.3 Tab 移不到目前頁裡的元素
  - 前提：觀眾視窗顯示 `counter`，焦點在講者視窗
  - 動作：按 Tab（Safari 按 Option+Tab）五次
  - 結果：焦點從來沒有移到目前頁、下一步與下一頁裡的計數器上
- PRES-R6.4 在觀眾視窗操作互動元件
  - 前提：觀眾視窗顯示 `counter`，這一頁有一個計數器，初始值是 0
  - 動作：在觀眾視窗把計數器按到 3
  - 結果：講者視窗的目前頁的計數器仍然顯示 0
- PRES-R6.5 觀眾視窗是黑畫面
  - 前提：講者視窗已經開著，觀眾視窗顯示 `intro`
  - 動作：在觀眾視窗按 `B`
  - 結果：講者視窗的目前頁仍然顯示 `intro`，上面疊著半透明的黑色遮罩，寫著「觀眾看到黑畫面」
- PRES-R6.6 下一頁的元件會攔下 → 時在講者視窗按下一步
  - 前提：`intro` 的下一頁 `gallery` 有一個輪播元件，在 `window` 的 keydown 事件遇到 → 時呼叫 `preventDefault()` 並換到下一張圖；焦點在講者視窗，觀眾視窗顯示 `intro`
  - 動作：按 →
  - 結果：觀眾視窗顯示 `gallery`，觀眾視窗與講者視窗目前頁裡的輪播都顯示第一張圖
- PRES-R6.7 目前頁的元件會攔下 → 時在講者視窗按下一步
  - 前提：觀眾視窗顯示 `gallery`，這一頁的輪播元件在 `window` 的 keydown 事件遇到 → 時呼叫 `preventDefault()` 並換到下一張圖，下一頁是 `recap`；焦點在講者視窗
  - 動作：按 →

  - 前提：`intro` 的下一頁 `repl` 有一個寫了 `autoFocus` 的文字輸入框，焦點在講者視窗，觀眾視窗顯示 `intro`
  - 動作：按 →
  - 結果：觀眾視窗顯示 `repl`

  - 前提：講者視窗已經開著，觀眾視窗顯示 `intro`
  - 動作：在觀眾視窗所在的瀏覽器視窗開一個新的分頁，再切回觀眾視窗的分頁
  - 結果：開新的分頁之後，講者視窗的目前頁仍然顯示 `intro`，上面疊著半透明的遮罩，寫著「觀眾看不到簡報」；切回觀眾視窗的分頁之後，遮罩消失
- PRES-R6.10 觀眾視窗縮到最小
  - 前提：講者視窗已經開著，觀眾視窗顯示 `intro`
  - 動作：把觀眾視窗縮到最小，再把它還原
  - 結果：縮到最小之後，講者視窗的目前頁上面疊著「觀眾看不到簡報」；還原之後，遮罩消失
- PRES-R6.11 黑畫面時觀眾視窗的分頁不在前景

  - 動作：在觀眾視窗所在的瀏覽器視窗切到另一個分頁，再切回觀眾視窗的分頁

- PRES-R6.12 觀眾視窗的分頁不在前景時在講者視窗換頁
  - 前提：講者視窗已經開著，觀眾視窗顯示 `intro`，下一頁是 `agenda`，講者在觀眾視窗所在的瀏覽器視窗切到另一個分頁
  - 動作：在講者視窗按 →，再切回觀眾視窗的分頁
  - 結果：按 → 之後，講者視窗的目前頁顯示 `agenda`，上面仍然疊著「觀眾看不到簡報」；切回來之後，觀眾視窗顯示 `agenda`，遮罩消失
- PRES-R6.13 觀眾視窗的分頁不在前景時重新整理講者視窗
  - 前提：講者視窗已經開著，觀眾視窗顯示 `intro`，講者在觀眾視窗所在的瀏覽器視窗切到另一個分頁
  - 動作：重新整理講者視窗
  - 結果：講者視窗載入完成之後 1 秒內，目前頁顯示 `intro`，上面疊著「觀眾看不到簡報」

> 設計理由：講者視窗的目前頁、下一步與下一頁都不能操作，因為講者示範互動元件時本來就看著投影幕操作，講者視窗的目前頁和投影幕不一致的影響不大。曾考慮讓目前頁可以操作，但兩個視窗的互動元件各有各的狀態，講者在講者視窗操作元件時，投影幕上的畫面不會改變。也考慮過把觀眾視窗裡互動元件的狀態同步到講者視窗，但這樣每個互動元件都要照一套同步規則實作。還考慮過用螢幕擷取把觀眾視窗的畫面即時顯示在講者視窗，但講者每次開啟講者視窗都要授權並挑選要擷取的視窗。完整討論見 [0004](../plans/archive/0004-presenter-mode.md)。

### PRES-R7 下一步與下一頁

「下一步」顯示觀眾視窗目前的頁面在下一步的畫面，也就是講者按下一步之後這一頁會出現的畫面。這一格和目前頁一樣 render 講者視窗自己的一份頁面（PRES-R6），所以不會顯示講者在觀眾視窗操作互動元件造成的改變。目前的頁面已經在最後一步，或沒有步驟時，這一格是灰底，寫著「沒有下一步」。「下一頁」顯示下一頁的第 0 步；目前的頁面是最後一頁時，這一格是灰底，寫著「簡報結束」。目前的頁面還有沒有下一步，依觀眾視窗目前 render 的步數決定，所以觀眾視窗的步數因為互動而改變時（STEP-R14），「下一步」也跟著改變；目前的步驟因此大於步數時，也當成已經在最後一步。

情境：

- PRES-R7.1 這一頁還有步驟
  - 前提：`list` 這一頁有 3 步，下一頁是 `recap`，觀眾視窗顯示 `list` 的第 1 步
  - 動作：按 `S`
  - 結果：「下一步」顯示 `list` 的第 2 步，「下一頁」顯示 `recap` 的第 0 步
- PRES-R7.2 已經在最後一步
  - 前提：`list` 這一頁有 3 步，下一頁是 `recap`，觀眾視窗顯示 `list` 的第 3 步
  - 動作：按 `S`
  - 結果：「下一步」是灰底，寫著「沒有下一步」；「下一頁」顯示 `recap` 的第 0 步
- PRES-R7.3 沒有步驟的頁面
  - 前提：`intro` 這一頁沒有步驟，下一頁是 `agenda`，觀眾視窗顯示 `intro`
  - 動作：按 `S`
  - 結果：「下一步」是灰底，寫著「沒有下一步」；「下一頁」顯示 `agenda` 的第 0 步
- PRES-R7.4 最後一頁
  - 前提：最後一頁 `finale` 有 2 步，觀眾視窗顯示 `finale` 的第 1 步
  - 動作：按 `S`
  - 結果：「下一步」顯示 `finale` 的第 2 步；「下一頁」是灰底，寫著「簡報結束」
- PRES-R7.5 觀眾視窗的步數變少
  - 前提：`toggle` 這一頁有 `<Step at={1}>`、`<Step at={2}>`，以及一個按下後移除 `<Step at={2}>` 的按鈕；講者視窗已經開著，觀眾視窗顯示 `toggle` 的第 1 步
  - 動作：在觀眾視窗按這個按鈕
  - 結果：講者視窗的「下一步」變成灰底，寫著「沒有下一步」
- PRES-R7.6 觀眾視窗的步數變得比目前的步驟少
  - 前提：`toggle` 這一頁有 `<Step at={1}>`、`<Step at={2}>`，以及一個按下後移除 `<Step at={2}>` 的按鈕；講者視窗已經開著，觀眾視窗顯示 `toggle` 的第 2 步
  - 動作：在觀眾視窗按這個按鈕
  - 結果：講者視窗的「下一步」變成灰底，寫著「沒有下一步」
- PRES-R7.7 觀眾視窗的步數因為互動變多
  - 前提：`expand` 這一頁有 `<Step at={1}>`，以及一個按下後加上 `<Step at={2}>` 的按鈕，`<Step at={2}>` 的內容是「補充說明」；講者視窗已經開著，觀眾視窗顯示 `expand` 的第 1 步
  - 動作：在觀眾視窗按這個按鈕
  - 結果：講者視窗的「下一步」不是灰底，畫面上沒有「補充說明」

> 設計理由：「下一步」與「下一頁」分成兩格，每一格顯示的內容固定，所以講者看一眼就知道下一次按下一步時會不會換頁：「下一步」是灰底時，講者再按下一步，觀眾就會看到「下一頁」那一格的畫面。
>
> 曾考慮只放一格，顯示講者下一次按下一步之後的畫面，但這一頁的步驟還沒走完時，講者看不到下一頁，而且這一格顯示的不論是這一頁的下一步還是下一頁，看起來都只是一張縮圖，講者要比對內容才分得出來會不會換頁。
>
> 也考慮過在沒有下一步時，讓右下角改顯示再下一頁，讓兩格不重複，但這樣講者按到最後一步、準備換頁時，下一頁的預覽會從右下角移到右上角。完整討論見 [0004](../plans/archive/0004-presenter-mode.md)。

### PRES-R8 資訊列

講者視窗最上方的資訊列照 PRES-R5 的圖，顯示經過時間（PRES-R9）與歸零按鈕、目前時刻、目前的頁碼與步驟，以及講者在講者視窗輸入中的頁碼（PRES-R3）。

- 目前時刻以 24 小時制顯示時與分，時與分都寫成兩位數，例如 `09:05`、`14:05`，0 點寫成 `00`，例如 `00:05`；目前時刻隨電腦的時間更新，不論經過時間有沒有在計時。
- 頁碼寫成「第 4 / 12 頁」，頁碼從 1 開始；目前的頁面有步驟時，旁邊再寫目前的步驟與步數，例如「第 1 / 3 步」，步數依觀眾視窗目前 render 的步數決定。目前的步驟大於步數時，例如步數因為互動變少（STEP-R14），步驟寫成和步數相同，例如「第 1 / 1 步」；步數因此變成 0 時，資訊列不顯示步驟。
- 講者在講者視窗輸入頁碼時，資訊列才顯示輸入中的頁碼，頁碼出現與消失的規則和觀眾視窗相同（NAV-R5），例如停止輸入 3 秒後，頁碼從資訊列消失。總覽開著時，輸入中的頁碼照 [overview.md](overview.md) 的 OVW-R19 顯示。

情境：

- PRES-R8.1 有步驟的頁面
  - 前提：簡報有 12 頁，第 4 頁有 3 步，觀眾視窗顯示第 4 頁的第 1 步

### PRES-R9 經過時間

資訊列上的經過時間可以點。經過時間在還沒開始計時時顯示「未開始」，講者點經過時間時開始計時；講者沒有點的話，觀眾視窗目前的頁面或步驟第一次改變時，經過時間自動開始計時，前提是這時講者視窗和觀眾視窗連線中。不論改變是講者在哪個視窗按下快捷鍵、按瀏覽器的上一頁，還是點頁面上的連結造成的，都會開始計時；畫面沒有換頁或換步驟時不會開始計時，例如黑畫面時按 → 只結束黑畫面、在最後一頁的最後一步按 →，或步數因為互動改變（STEP-R14）。講者點歸零按鈕時，經過時間回到「未開始」，之後同樣在講者點經過時間，或觀眾視窗的頁面或步驟下一次改變時開始計時。

經過時間未滿一小時時寫成「分:秒」，例如 `00:05`、`12:34`；滿一小時之後寫成「時:分:秒」，例如 `1:00:00`、`1:02:03`。分與秒一律寫成兩位數，時不補零。講者在計時中點經過時間沒有作用，要重新計時時，講者點歸零按鈕。

經過時間一律從開始計時的那一刻算起，而且只屬於同一個分頁裡的同一份簡報：

- 觀眾視窗或講者視窗重新整理，或講者關掉講者視窗、之後再按 `S` 開啟時，經過時間都包含重新整理或講者視窗關著的那段時間。
- 講者在新的分頁或視窗開啟簡報，或在同一個分頁換到另一份簡報時，經過時間顯示「未開始」。
- 講者用瀏覽器還原誤關的觀眾視窗時，經過時間接續。

不過講者複製觀眾視窗的分頁時，複製出來的分頁沿用原分頁的經過時間。

- PRES-R9.20 講者視窗重新整理途中換頁

  - 結果：觀眾視窗顯示 `agenda`，講者視窗的經過時間顯示「未開始」
- PRES-R9.21 在總覽裡移動選取框
  - 前提：講者視窗已經開著，焦點在講者視窗，經過時間顯示「未開始」，觀眾視窗顯示 `intro`
  - 動作：按 `G`，按 →，再按 `G`，等 5 秒
  - 結果：觀眾視窗顯示 `intro`，經過時間仍然顯示「未開始」
- PRES-R9.22 從總覽跳到其他頁面時開始計時
  - 前提：講者視窗已經開著，焦點在講者視窗，經過時間顯示「未開始」，觀眾視窗顯示 `intro`，下一頁是 `agenda`
  - 動作：按 `G`，按 →，按 Enter，等 5 秒
  - 結果：觀眾視窗顯示 `agenda`，經過時間顯示 `00:05`

> 設計理由：講者通常在開講前就開好講者視窗，所以經過時間先停在「未開始」，講者在標題頁開講時點經過時間開始計時；講者忘了點的話，第一次換頁或換步驟時也會開始計時，不會整場都沒有經過時間。
>
> 代價是講者在講者視窗開著時測試翻頁器，經過時間就會開始，測試完要點歸零按鈕。
>
> 曾考慮在開啟講者視窗時就開始計時，但這樣講者每一場都要在開講時歸零，忘了歸零的話，經過時間會多出整段準備時間。
>
> 也考慮過只在講者點經過時間時開始，但講者忘了點的話，要等到看資訊列時才會發現。
>
> 還考慮過只在第一次換頁時開始，但這樣講者在標題頁講的時間不會算進去。
>
> 開啟講者視窗之前，或講者視窗重新整理、還沒連上觀眾視窗時的換頁不會開始計時，因為講者這時看不到經過時間，不知道它已經開始。
>
> 經過時間不能暫停，因為授課中途休息時，講者看目前時刻就能掌握時間。完整討論見 [0004](../plans/archive/0004-presenter-mode.md)。

### PRES-R10 講者備註

備註區顯示觀眾視窗目前頁面的講者備註，備註的寫法寫在 [framework.md](framework.md) 的 FRAME-R6。

- 播放器照 CommonMark 把備註的 Markdown 轉成格式化的文字；備註裡的 HTML 標籤不會 render，照原文顯示；備註裡的圖片不會顯示，在圖片的位置顯示圖片的替代文字。
- 講者點備註裡 `#/` 開頭的連結時，觀眾視窗跳到連結指向的頁面，和講者點頁面裡的同一個連結相同（NAV-R1）。這種連結另有以下規則：
  - 講者按著 Cmd、Ctrl 或 Shift 點，或用滑鼠中鍵點時，結果也一樣，瀏覽器不會開啟新的分頁或視窗。
  - 連結指向不存在的頁面時，觀眾視窗不換頁，也不新增瀏覽紀錄，只在觀眾視窗的 console 印出警告（NAV-R2）。
  - 連結指向的頁面與步驟照 NAV-R1 與 STEP-R10 到 STEP-R13 決定之後，和觀眾視窗目前的頁面與步驟相同時，觀眾視窗也不新增瀏覽紀錄，那幾條需求要印出的警告照常印在觀眾視窗的 console。
  - 連線中斷時，點這種連結沒有作用（PRES-R12）。
  - 講者點這種連結跳頁，和講者在講者視窗跳頁一樣，適用 PRES-R3 第 3 點寫的 Chromium 上一頁按鈕的例外。
- 備註裡的其他連結不能點，備註區顯示連結的文字，後面用括號寫出網址，例如 `[MDN](https://developer.mozilla.org)` 顯示成 `MDN（https://developer.mozilla.org）`；連結的文字和網址相同時，例如 `<https://example.com>`，只顯示一次網址。
- 頁面沒有備註，或 `notes` 是空字串、只有空白與換行時，備註區寫著「這一頁沒有備註」。

> 設計理由：備註裡 `#/` 開頭以外的連結不能點，因為講者視窗是沒有分頁列的彈出視窗，講者在彈出視窗裡點會開新分頁的連結時，Chromium 與 Firefox 可能把新分頁加進觀眾視窗所在的瀏覽器視窗，投影幕就會改顯示外部網頁，觀眾視窗也離開全螢幕。
>
> 曾考慮由播放器另外開一個新的瀏覽器視窗開啟外部連結，但要給觀眾看的網頁本來就要在投影幕上開，只給講者看的參考資料，講者可以照備註寫出的網址自己開啟。
>
> 備註裡的圖片不顯示，因為用相對路徑寫的圖片不會經過 Vite 處理，載入不到，用外部網址寫的圖片要連網才看得到，違反 DIST-R1。完整討論見 [0004](../plans/archive/0004-presenter-mode.md)。

備註比備註區長時，講者用觸控板或滑鼠滾輪捲動備註區。講者按下的快捷鍵不會捲動備註區，例如 PageDown、Space 與 ↓ 只會換頁或換步驟。換到其他頁面時，備註區捲回最上方；換到同一頁的其他步驟時，備註區維持原本的捲動位置。

### PRES-R11 講者視窗的按鈕與連結不取得焦點

講者視窗裡的經過時間、歸零按鈕與備註裡的連結都不取得焦點，講者用滑鼠或手指點過之後也一樣。講者視窗也擋下 Tab 與 Shift+Tab，在 Safari 另外擋下 Option+Tab 與 Option+Shift+Tab，焦點一直留在網頁裡，不會移到這些元素，也不會移到瀏覽器的網址列。所以講者在講者視窗按 Space 或 Enter 時，不會按下按鈕或開啟連結，而是照 PRES-R3 觸發快捷鍵。

> 設計理由：講者用 Tab 也沒辦法把焦點移到講者視窗裡的按鈕與連結，因為這些元素可以用 Tab 移到的話，講者誤按 Tab 時焦點會移到歸零按鈕，講者接著按 Space 想換頁，結果是經過時間歸零，投影幕卻沒有換頁。
>
> 曾考慮照 NAV-R11 的全螢幕按鈕，讓這些元素可以用 Tab 移到，但觀眾視窗要讓 Tab 移到頁面上的互動元件，講者視窗裡則沒有需要用 Tab 移到的元素。
>
> 講者視窗擋下 Tab，因為網頁裡沒有可以取得焦點的元素時，講者在 Chrome 與 Firefox 按 Tab 時，瀏覽器可能把焦點移到網址列，之後講者按的鍵都送不到網頁。完整討論見 [0004](../plans/archive/0004-presenter-mode.md)。

### PRES-R12 連線中斷時保留最後的畫面

講者視窗連不上觀眾視窗時，例如觀眾視窗正在重新整理，或講者在觀眾視窗按瀏覽器的上一頁離開了簡報，講者視窗保留最後收到的畫面與備註，上面疊一條「連線中斷」的提示；觀眾視窗開始重新整理或離開簡報之後 1 秒內，講者視窗疊上這條提示。

以下情況的結果和上面不同：

- 連線中斷時重新整理講者視窗的話，講者視窗沒有最後收到的畫面可以保留，所以目前頁、下一步、下一頁、備註區，以及資訊列的經過時間、頁碼與步驟都是空的，資訊列只顯示目前時刻，上面疊一條「連線中斷」的提示；觀眾視窗回到簡報之後，講者視窗照常恢復連線。
- 講者視窗連上觀眾視窗時，如果發現兩個視窗載入的 slidetray 是不同次 build 的，例如講者重新 build 之後只重新整理了其中一個視窗，講者視窗也比照連線中斷處理，提示改寫「兩個視窗的簡報版本不同，請用 Ctrl+R（macOS 用 Cmd+R）重新整理兩個視窗」。講者視窗開啟或重新整理之後，第一次連上觀眾視窗就發現版本不同時，講者視窗沒有收到過畫面，所以目前頁、下一步、下一頁、備註區，以及資訊列的經過時間、頁碼與步驟都是空的，資訊列只顯示目前時刻。講者照提示重新整理視窗之後，兩個視窗載入的版本相同時，講者視窗照常恢復連線。
- 觀眾視窗卡住時，例如頁面裡的元件讓頁面的 JS 連續執行好幾秒，講者視窗也跟著停住，講者在這段期間的操作，例如按下快捷鍵或點歸零按鈕，等觀眾視窗恢復回應之後才作用。
- 觀眾視窗的分頁 crash 時，講者視窗也跟著 crash，講者視窗重新整理之前，不會照本 spec 的任何規則動作，例如觀眾視窗之後被關閉時，講者視窗不會跟著關閉（PRES-R13）。講者視窗重新整理之後，照本 spec 的規則動作：觀眾視窗也重新整理之後，講者視窗照常恢復連線；觀眾視窗已經關閉的話，講者視窗只顯示 PRES-R14 的提示。

連線中斷的期間另有以下規則：

- 需要觀眾視窗執行的快捷鍵沒有作用，例如換頁、跳頁、切換黑畫面與輸入頁碼。不過全螢幕的快捷鍵照常作用在講者視窗（PRES-R4），播放器也照常擋下瀏覽器用 F5 重新整理網頁的行為（NAV-R10）。
- 連線中斷時，講者視窗輸入中的頁碼取消。
- 講者點經過時間、歸零按鈕或備註裡 `#/` 開頭的連結都沒有作用，經過時間照常累計。

- 觀眾視窗回到同一份簡報、載入完成之後 1 秒內，講者視窗恢復連線，顯示觀眾視窗目前的位置。觀眾視窗改播另一份簡報時，則照 PRES-R13 處理。
- 講者視窗開啟或重新整理、載入完成之後 1 秒內，講者視窗連上觀眾視窗，兩個視窗的版本相同時，顯示觀眾視窗目前的位置。

### PRES-R13 觀眾視窗關閉或改播另一份簡報時講者視窗跟著關閉

觀眾視窗關閉，或在同一個分頁改播另一份簡報時，講者視窗在 1 秒內跟著關閉。以下情況另有規則：

- 觀眾視窗的分頁 crash 時，講者視窗的行為寫在 PRES-R12。
- 觀眾視窗重新整理，或離開簡報、停在其他網頁時，講者視窗不會關閉，而是照 PRES-R12 處理；觀眾視窗停在其他網頁時被關閉，講者視窗一樣跟著關閉。
- 觀眾視窗連到回應 `Cross-Origin-Opener-Policy` 的網頁時，不論講者是點頁面裡的連結、從網址列或書籤，還是用瀏覽器的上一頁或下一頁連過去，瀏覽器可能切斷兩個視窗之間的關係；這時講者視窗沒辦法區分這種情況和觀眾視窗關閉，所以也會跟著關閉，講者回到簡報之後再按 `S` 開啟講者視窗。

情境：

- PRES-R13.1 關閉觀眾視窗
  - 前提：講者視窗已經開著
  - 動作：關閉觀眾視窗
  - 結果：1 秒內，講者視窗跟著關閉
- PRES-R13.2 觀眾視窗改播另一份簡報
  - 前提：網站上有 `annual-review` 與 `demo` 兩份簡報，觀眾視窗播放 `annual-review`，已經開啟講者視窗
  - 動作：在觀眾視窗按瀏覽器的上一頁回到網站首頁，再點 `demo`
  - 結果：回到網站首頁時，講者視窗顯示「連線中斷」；觀眾視窗開始播放 `demo` 之後，講者視窗跟著關閉
- PRES-R13.3 觀眾視窗停在其他網頁時被關閉
  - 前提：觀眾視窗從簡報回到網站首頁，講者視窗顯示「連線中斷」
  - 動作：關閉觀眾視窗
  - 結果：講者視窗跟著關閉
- PRES-R13.4 觀眾視窗從網址列連到回應 COOP 的網站
  - 前提：講者視窗已經開著，觀眾視窗顯示 `intro`
  - 動作：在觀眾視窗的網址列輸入一個回應 `Cross-Origin-Opener-Policy: same-origin` 的網址，再按瀏覽器的上一頁回到簡報，按 `S`
  - 結果：連到那個網址之後，講者視窗跟著關閉；按 `S` 之後，開啟新的講者視窗，目前頁顯示 `intro`
- PRES-R13.5 用瀏覽器的上一頁回到回應 COOP 的網頁
  - 前提：講者從一個回應 `Cross-Origin-Opener-Policy: same-origin` 的網頁點連結開啟簡報，再按 `S` 開啟講者視窗
  - 動作：在觀眾視窗按瀏覽器的上一頁回到那個網頁
  - 結果：講者視窗跟著關閉
- PRES-R13.6 點頁面裡連到回應 COOP 的網站的連結
  - 前提：講者視窗已經開著，觀眾視窗顯示 `intro`，這一頁有一個連到回應 `Cross-Origin-Opener-Policy: same-origin` 的網址的連結
  - 動作：在觀眾視窗點這個連結
  - 結果：講者視窗跟著關閉

> 設計理由：觀眾視窗關閉時講者視窗跟著關閉，因為講者每場演講結束時都會關掉觀眾視窗，講者視窗留著的話，講者還得再關一次。曾考慮保留講者視窗並疊上「觀眾視窗已關閉」，讓講者誤關觀眾視窗時，還看得到剛才講到第幾頁與已經講了多久，但講者在台上誤關觀眾視窗的情況很少見，而且講者重新開啟簡報、按 `S` 之後，畫面上會同時有舊的與新的講者視窗。
>
> 觀眾視窗在同一個分頁改播另一份簡報時，講者視窗也跟著關閉，因為講者視窗只能顯示開啟它的那份簡報，留著也沒辦法連上新的簡報。完整討論見 [0004](../plans/archive/0004-presenter-mode.md)。

### PRES-R14 網址帶 `?presenter` 但沒有開啟它的觀眾視窗

講者視窗的網址是 slidetray 的 `index.html` 加上 `?presenter`。以下這些網址帶 `?presenter` 的視窗只顯示「請在簡報裡按 S 開啟講者視窗」：

- 不是從觀眾視窗開啟的視窗，例如講者用瀏覽器重新開啟的講者視窗（macOS 是 Cmd+Shift+T），或講者從瀏覽紀錄開啟講者視窗網址的視窗。
- 開啟講者視窗的觀眾視窗已經關閉之後才重新整理的講者視窗，這只會發生在觀眾視窗的分頁 crash 之後（PRES-R12）。

在這種視窗裡，播放器的快捷鍵都不觸發，講者按下的按鍵都交給瀏覽器。講者照提示在觀眾視窗按 `S` 時，即使這種視窗還開著，播放器也照常開啟新的講者視窗；這種視窗維持原狀，由講者自己關掉。

情境：

- PRES-R14.1 直接開啟講者視窗的網址
  - 前提：簡報已經 build 好
  - 動作：在瀏覽器的網址列開啟 slidetray 的 `index.html?presenter`
  - 結果：畫面只顯示「請在簡報裡按 S 開啟講者視窗」
- PRES-R14.2 重新開啟關掉的講者視窗
  - 前提：觀眾視窗已經開啟講者視窗
  - 動作：關掉講者視窗，按 Cmd+Shift+T
  - 結果：重新開啟的視窗只顯示「請在簡報裡按 S 開啟講者視窗」
- PRES-R14.3 重新開啟的視窗還開著時在觀眾視窗按 `S`
  - 前提：觀眾視窗顯示 `agenda`，已經開啟講者視窗；講者關掉講者視窗，再按 Cmd+Shift+T，重新開啟的視窗只顯示「請在簡報裡按 S 開啟講者視窗」
  - 動作：在觀眾視窗按 `S`
  - 結果：開啟新的講者視窗，目前頁顯示 `agenda`；用 Cmd+Shift+T 重新開啟的視窗仍然只顯示「請在簡報裡按 S 開啟講者視窗」
- PRES-R14.4 在直接開啟的講者視窗網址按 `F`
  - 前提：在瀏覽器的網址列開啟 slidetray 的 `index.html?presenter`，畫面只顯示「請在簡報裡按 S 開啟講者視窗」
  - 動作：按 `F`
  - 結果：這個視窗沒有進入全螢幕

> 設計理由：這種視窗只顯示提示，請講者回到觀眾視窗按 `S`，因為會開到這種視窗的，通常是誤關了講者視窗、想用 Cmd+Shift+T 找回來的講者，這時投影幕上的觀眾視窗還開著。講者誤關觀眾視窗時，講者視窗跟著關閉（PRES-R13），講者按 Cmd+Shift+T 也可能先開到這種視窗，再按一次才還原觀眾視窗。
>
> 曾考慮拿掉網址的 `?presenter`，把這個視窗換成觀眾視窗，但這樣筆電上會多出第二個從第一頁開始播放的觀眾視窗；講者在這個視窗按 `S` 的話，開出的講者視窗控制的是筆電上的這個視窗（PRES-R15），投影幕上的觀眾視窗不會跟著換頁。完整討論見 [0004](../plans/archive/0004-presenter-mode.md)。

### PRES-R15 一個講者視窗只控制開啟它的觀眾視窗

同一份簡報開在好幾個分頁或視窗時，每個講者視窗只顯示並操作開啟它的那個觀眾視窗；講者可以在每個觀眾視窗各自按 `S`，開啟這個觀眾視窗自己的講者視窗。

情境：

- PRES-R15.1 兩個分頁各自開啟講者視窗
  - 前提：同一份簡報開在兩個分頁，兩個分頁都顯示 `intro`，下一頁是 `agenda`
  - 動作：在第一個分頁按 `S`，在第二個分頁按 `S`，再在第一個分頁開啟的講者視窗按 →
  - 結果：開啟兩個講者視窗；第一個分頁顯示 `agenda`，第二個分頁仍然顯示 `intro`

> 設計理由：講者視窗只控制開啟它的觀眾視窗。曾考慮讓一個講者視窗控制同一份簡報的所有分頁，但從 `file://` 開啟時，`BroadcastChannel` 在 WebKit 收不到訊息，而 `localStorage` 在 Chromium 與 WebKit 由所有 `file://` 網頁共用，用 `localStorage` 傳訊息的話，講者視窗會連其他簡報的分頁一起控制。講者要把同一個畫面投到兩個螢幕時，用作業系統的鏡像輸出。完整討論見 [0004](../plans/archive/0004-presenter-mode.md)。
